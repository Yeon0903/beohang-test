버항 V3.0 Alpha — 실제 재생 집계 1차 개발본

적용 전: Supabase 데이터베이스 백업 권장. 기존 공개 노래 테이블(virhang_published_tracks)이 있어야 합니다.
1. Supabase SQL Editor에서 V3.0_RANKING_BACKEND_SETUP.sql 실행.
2. 기존 virhang-auth.js의 Publishable Key 설정이 정상인지 확인(비밀 키를 브라우저에 입력하지 마세요).
3. 이 폴더에서 python -m http.server 5500 실행 후 http://localhost:5500 접속.
4. 로그인 후 Supabase에 공개 등록된 YouTube 노래 재생 (샘플곡/로컬 저장곡 제외).
5. 정상적으로 재생한 뒤 약 30초 이상 듣고 랭킹 탭을 확인. 같은 곡도 새로 재생하고 30초 이상 정상 재생하면 다시 집계됨.
6. 회원이 로그인하지 않으면 재생수 집계 안 됨. SOOP 클립은 외부 사이트에서 열리므로 집계 안 됨.

현재 한계:
- 이 방식은 브라우저의 YouTube 상태 이벤트와 서버의 경과 시간을 사용합니다. 100% 실제 청취 증명은 아닙니다.
- '좋아요' 랭킹은 회원별 좋아요가 현재 클라이언트/라이브러리 JSON에 저장되어 서버 공통 집계 테이블이 없으므로 아직 연결하지 않았습니다.
- 순위 변동/NEW 표시용 시간대별 순위 스냅샷은 아직 구현되지 않았습니다.
- 인기 랭킹은 가짜 시연용 조회수 대신 실제 집계된 공개곡만 표시합니다.
- 인증 회원에게만 재생 수가 쌓이고 30초 미만, 일시정지 중, 탐색 점프 시간은 집계하지 않도록 처리했습니다.
- SOOP 클립과 유튜브의 재생 차이를 감안해 공정한 교차 플랫폼 순위는 추후 별도 설계가 필요합니다.
- 기존 실험용 '재생 15분 제한 해제 SQL'은 정식 공개 전 반드시 복원해야 합니다.

새 SQL은 기존 회원/노래 행을 삭제하지 않습니다.

재생 제한 변경: 기존 랭킹 SQL을 이미 적용했다면 V3.0_ALLOW_REPLAYS.sql만 실행하세요. 아직 적용하지 않았다면 V3.0_RANKING_BACKEND_SETUP.sql을 실행하세요. 두 개 모두 실행할 필요는 없습니다.
