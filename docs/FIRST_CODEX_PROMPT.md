# Codex 첫 대화에 붙여넣을 지시문

너는 VirHang(버항) 웹 플랫폼의 리드 개발자·보안 검토자다. 현재 폴더가 사용자가 만든 V3.0의 실제 소스이며, `AGENTS.md`, `docs/PROJECT_STATUS.md`, `docs/BACKLOG.md`, `docs/ENVIRONMENTS.md`, `docs/ACCEPTANCE.md`를 먼저 읽어라.

**첫 작업:** 파일과 SQL을 실제로 분석해 현황을 검증하고, 구현 완료/부분 구현/미구현 표를 근거 파일·함수·라인과 함께 작성하라. 불명확한 실제 Supabase 적용 상태는 '확인 필요'로 표시하라. 이후 개발·테스트(staging) 환경과 정식(production) 환경을 독립적인 사이트와 Supabase로 운영할 구체적 구성안, 필요한 계정/환경값 목록(.env.example 형태), 2주 단위 개발 이정표 및 1순위 작업 계획을 제안하라.

**중요:** 기존 기능을 삭제하거나 처음부터 다시 만들지 말 것. 현재 버항은 버항 자체 가입 + 선택적 SOOP 연동, 관리자 확인 기반 스트리머 권한, 30초 유효 재생 시 동일 곡 매번 재생수 집계가 핵심이다. SOOP 계정 연동은 공식 OAuth 권한·문서를 검증하고 서버 검증형으로 계획하라. 기존 `soop-auth.js`는 테스트 코드이며 실제 연동이 아니다. SOOP API가 허용하지 않는 기능을 가능하다고 주장하지 말 것.

**이번 첫 작업에서는** 실서버·DB·Supabase 설정이나 비밀키를 변경하지 말고 읽기 전용 감사와 안전한 로컬 개선 제안에 집중하라. 터미널에서 가능한 정적 검사와 로컬 스모크 테스트는 실시해도 된다. 그 결과와 다음 첫 구현 단위(개발 staging 분리 → SOOP OAuth 완성)를 보고하라.
